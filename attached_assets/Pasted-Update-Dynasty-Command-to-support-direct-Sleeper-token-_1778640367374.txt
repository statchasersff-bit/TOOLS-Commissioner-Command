Update Dynasty Command to support direct Sleeper token authentication, but build it with an endpoint adapter so we can safely configure the exact Sleeper auth/action endpoints after discovery.

Context:
Sleeper has approved us to obtain/use tokens from their API, but they did not provide exact endpoint documentation. Their public docs say the public API is read-only, so authenticated write endpoints must be discovered/tested and isolated in one config layer.

Build:

1. Sleeper Auth UI
Add a “Connect Sleeper” card inside Dynasty Command.

Disconnected state:
- Title: Connect Sleeper
- Text: Connect your Sleeper account to sync leagues and unlock Dynasty Command actions.
- Button: Connect Sleeper

Modal copy:
- “Authentication Required”
- “To make changes on Sleeper, you need to connect your Sleeper account.”
- “Your credentials are sent directly to Sleeper. Auth tokens are stored locally in your browser.”
- Inputs:
  - Sleeper username, email, or phone
  - Code/password/token field depending on selected method
- Buttons:
  - Send Code
  - Use token manually
  - Connect
  - Cancel

Connected state:
- Connected as @username
- Sync My Leagues
- Disconnect

2. Create endpoint config file

Create:
src/config/sleeperAuthEndpoints.ts

Use placeholders like:

export const SLEEPER_AUTH_ENDPOINTS = {
  requestCode: "",
  verifyCode: "",
  login: "",
  validateToken: "",
  refreshToken: "",
  logout: "",
};

export const SLEEPER_ACTION_ENDPOINTS = {
  setLineup: "",
  submitWaiver: "",
  proposeTrade: "",
  acceptTrade: "",
  rejectTrade: "",
  draftPick: "",
  sendChatMessage: "",
};

Do not scatter endpoint URLs throughout the app. Every authenticated Sleeper call must go through this config file.

3. Create auth service

Create:
src/services/sleeperAuth.ts

Functions:
- requestSleeperCode(identifier)
- verifySleeperCode(identifier, code)
- loginWithToken(token)
- validateSleeperToken(token)
- getSleeperSession()
- saveSleeperSession()
- clearSleeperSession()
- logoutSleeper()

Token storage:
- localStorage key: statchasers_sleeper_auth
- Store:
  - token
  - user_id
  - username
  - avatar
  - connected_at
  - expires_at if available

Security:
- Never console.log credentials
- Never console.log tokens
- Never send Sleeper credentials through our backend
- All token actions must be client-side unless explicitly changed later
- Add clear disconnect behavior
