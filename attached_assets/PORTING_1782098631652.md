# Porting the Dispersal Draft Tool to another project

This document explains how to copy the **Dispersal Draft** tool out of this repo and into
another codebase. "The tool" is not a single file — it's a pnpm-workspace full-stack app
made of 4 internal libraries, an Express + Socket.io API server, and a React + Vite
frontend. Porting it is mostly a packaging + wiring job.

Hand the **"Instructions for the receiving project's Claude"** section (below) to the
Claude in the target repo after you've dropped in the files listed under
**"Files to send over."**

---

## What this tool is

A dynasty fantasy-football commissioner tool for running dispersal drafts: commissioners
create a draft room, add orphan-team assets, share a private link, managers claim slots,
and a live draft board updates in real time over Socket.io.

### Architecture
- pnpm workspaces, Node 24, TypeScript 5.9.
- 4 internal packages under `lib/`:
  - `@workspace/db` — PostgreSQL + Drizzle ORM. Tables: `draft-rooms`,
    `draft-participants`, `draft-assets`, `draft-picks`, `chat-messages`.
  - `@workspace/api-zod` — Zod (`zod/v4`) request/response schemas (incl. `src/generated/`).
  - `@workspace/api-client-react` — generated TanStack Query hooks + a custom fetch.
  - `@workspace/api-spec` — `lib/api-spec/openapi.yaml` is the source of truth; Orval
    generates the hooks (api-client-react) and zod schemas (api-zod).
- `artifacts/api-server` — Express 5 + Socket.io. WebSocket path is `/api/ws`. Bundled
  with esbuild via `build.mjs` (do **not** use `app.listen` — see gotchas).
- `artifacts/stat-chasers` — React + Vite + Wouter + TanStack Query + Tailwind v4 +
  socket.io-client + shadcn/ui. Sleeper league import is **client-side**
  (`src/lib/sleeper.ts` hits the public Sleeper API). The server only stores
  `sleeperLeagueId`-type fields — there is no server-side Sleeper integration to port.

## Files to send over

The cleanest transfer is to **send the whole repo** (it's small). If extracting, send
these in full, **preserving paths**:

**Root (workspace wiring — required):**
- `package.json`, `pnpm-workspace.yaml` (contains the dependency **catalog** + overrides —
  critical), `tsconfig.json`, `tsconfig.base.json`, `.npmrc`, `pnpm-lock.yaml`
- `scripts/` (post-merge db push helper)
- `replit.md` (architecture doc — useful context for the receiving Claude)
- this `PORTING.md`

**Internal libraries (`lib/`) — required, all four:**
- `lib/db/` — Drizzle schema (5 tables) + `drizzle.config.ts`
- `lib/api-zod/` — Zod schemas (incl. `src/generated/`)
- `lib/api-client-react/` — generated TanStack Query hooks + `custom-fetch.ts`
- `lib/api-spec/` — `openapi.yaml` + `orval.config.ts`

**API server (`artifacts/api-server/`) — required:**
- All of `src/` (routes, `lib/socket.ts`, `lib/pause-window.ts`, `lib/draft-utils.ts`,
  etc.), `build.mjs`, `package.json`, `tsconfig.json`, `.replit-artifact/artifact.toml`

**Frontend (`artifacts/stat-chasers/`) — required:**
- All of `src/`, `index.html`, `vite.config.ts`, `components.json`, `package.json`,
  `tsconfig.json`, `.replit-artifact/artifact.toml`
- `public/` (logo, favicon, opengraph)
- `attached_assets/statchasers_logo_transparent_dark_1778467396432.png` — the **only**
  attached asset actually imported (via the `@assets` alias in `home.tsx`). Skip the other
  files in `attached_assets/`.

**Do NOT send:** `artifacts/mockup-sandbox/` (design scratchpad, unused), any
`node_modules/`, `dist/`, `.cache/`, `.git/`, `tsconfig.tsbuildinfo`.

## Instructions for the receiving project's Claude

> Copy the block below into the target repo's Claude after the files above are in place.

```markdown
I'm importing a full-stack "Dispersal Draft" tool from another pnpm-workspace repo.
It's a dynasty fantasy-football commissioner tool: create a draft room, add orphan-team
assets, share a private link, managers claim slots, and a live draft board updates in
real time over Socket.io. Please integrate it. Here is the architecture and the steps.

## Architecture
- pnpm workspaces, Node 24, TypeScript 5.9.
- 4 internal packages under lib/:
  - @workspace/db        — PostgreSQL + Drizzle ORM. Tables: draft-rooms,
                           draft-participants, draft-assets, draft-picks, chat-messages.
  - @workspace/api-zod   — Zod (zod/v4) request/response schemas (has src/generated/).
  - @workspace/api-client-react — generated TanStack Query hooks + a custom fetch.
  - @workspace/api-spec  — lib/api-spec/openapi.yaml is the source of truth; Orval
                           generates the hooks (api-client-react) and zod (api-zod).
- artifacts/api-server   — Express 5 + Socket.io. WebSocket path is /api/ws. Bundled
                           with esbuild via build.mjs (NOT app.listen — see gotchas).
- artifacts/stat-chasers — React + Vite + Wouter + TanStack Query + Tailwind v4 +
                           socket.io-client + shadcn/ui. Sleeper league import is
                           client-side (src/lib/sleeper.ts hits the public Sleeper API).

## Integration steps
1. FIRST detect this repo's shape. Is it ALSO a pnpm workspace? Run:
   cat pnpm-workspace.yaml package.json 2>/dev/null; ls lib artifacts 2>/dev/null
   - If yes: merge the incoming `packages:` globs, the `catalog:` block, and the
     `overrides`/`onlyBuiltDependencies` from the incoming pnpm-workspace.yaml into this
     repo's. Do NOT blindly overwrite — reconcile versions.
   - If this is NOT a pnpm workspace (e.g. single-package npm/yarn): you must either
     convert it to pnpm workspaces, or flatten — replace every `workspace:*` dependency
     with a relative path / inline the lib code, and replace every `catalog:` version
     specifier with the concrete version from the incoming workspace's `catalog:` map.
     The `catalog:` and `workspace:*` protocols ONLY work under pnpm workspaces.

2. Install deps with pnpm (this app enforces pnpm via a preinstall guard; npm/yarn will
   be rejected). Run: pnpm install

3. Database: this needs Postgres. Set env DATABASE_URL to a Postgres connection string.
   Then push the schema (dev): pnpm --filter @workspace/db run push
   Review lib/db/src/schema/*.ts first to confirm no table-name collisions with this repo.

4. Env vars required:
   - DATABASE_URL — Postgres (api-server)
   - api-server listens on PORT (default 8080)
   - frontend vite.config.ts REQUIRES PORT and BASE_PATH env vars or it throws. Set e.g.
     PORT=22582 BASE_PATH=/  (BASE_PATH is the URL base path the SPA is served under).

5. Routing/reverse-proxy: the frontend talks to the API and opens a Socket.io connection
   at /api/ws. Make sure your dev/prod proxy forwards BOTH /api and the /api/ws WebSocket
   upgrade to the api-server port. (In the source repo this is declared in each
   .replit-artifact/artifact.toml `paths` array — adapt to your proxy/router.)

6. Replit-specific bits to neutralize if you are NOT on Replit:
   - frontend package.json depends on @replit/vite-plugin-cartographer,
     @replit/vite-plugin-dev-banner, @replit/vite-plugin-runtime-error-modal, and
     vite.config.ts imports them. The cartographer/dev-banner are already guarded behind
     `process.env.REPL_ID !== undefined`, so they no-op off-Replit, but
     runtimeErrorOverlay is imported unconditionally — keep the dep installed or remove
     that plugin line.
   - The .replit-artifact/artifact.toml files are Replit deployment manifests; replace
     with your own process manager / Docker / proc definitions. Useful info inside them:
     dev commands, build commands, ports, the /api + /api/ws paths, and the SPA rewrite
     (all routes -> /index.html).

7. Run it (dev):
   - API:      pnpm --filter @workspace/api-server run dev   (builds with esbuild, port 8080)
   - Frontend: PORT=5173 BASE_PATH=/ pnpm --filter @workspace/stat-chasers run dev
   - Typecheck everything: pnpm run typecheck
   - Build everything:     pnpm run build

## Gotchas (these will bite you)
- Socket.io: do NOT call app.listen() directly. The entry wraps the Express app in
  createServer(app) and passes the server to initSocket() (src/lib/socket.ts). Keep that.
- WebSocket path is hard-coded to /api/ws; it must be reachable through your proxy.
- API codegen: if you regenerate from openapi.yaml via
  `pnpm --filter @workspace/api-spec run codegen`, Orval rewrites
  lib/api-zod/src/index.ts with stale references — manually restore it to just:
  `export * from "./generated/api";`  (export only ./generated/api, not ./generated/types,
  to avoid duplicate-export conflicts).
- Commissioner auth is a secret token stored in localStorage and passed in request
  bodies — there are no user accounts. If your app has real auth, you'll want to bridge it.
- Draft order is randomly shuffled server-side when the commissioner starts; snake vs
  linear ordering is handled in the pick-ordering logic (routes/picks.ts).
- Tailwind v4 (via @tailwindcss/vite) — if this repo uses Tailwind v3, the styling setup
  (index.css @import, components.json) differs and must be reconciled.

After wiring, verify: pnpm run typecheck passes, the API health endpoint /api/healthz
returns ok, and the frontend loads the draft-room create page.
```
